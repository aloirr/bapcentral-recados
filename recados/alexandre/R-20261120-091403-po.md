# Gravar recados com git push no clone anexado (não pela API): orientação do Alexandre

## Contexto

"O problema não é o token nem o ambiente. Neste projeto eu gravo os recados com o próprio `git`, e o outro projeto está tentando gravar pela API do GitHub. O proxy da nuvem bloqueia essa segunda forma, com qualquer token."
"O gerente de lá tem o mesmo problema e se resolve do mesmo jeito: gravar com `git push` no repositório de recados anexado, e não pelo `coord.mjs`."
Autorização dele para o po, nesta sessão: gravar os recados direto no main do aloirr/bapcentral-recados por git.

## O que preciso / o que mudou
1. **Para gravar recado e lidos, use git no clone do aloirr/bapcentral-recados anexado à sessão**, e não o `coord.mjs enviar`/`lido` (a API REST dá 403 no proxy):
   1. `git pull -q --rebase origin main`;
   2. crie `recados/<destino>/<id>.md` (um por destino, no formato da CLI) ou acrescente o id em `lidos/<agente>.txt`;
   3. `git -c user.name=alexandre -c user.email=alexandre@bapcentral.invalid commit -m "recados: <id>"`;
   4. `git push origin HEAD:main`;
   5. `git fetch` e `git status`: tem de ficar igual ao origin/main.
   Para ler, `coord.mjs` (caixa, pendencias, ler, fio) continua valendo.
2. Para gravar no main, a sua sessão precisa da mesma autorização escrita do Alexandre; sem ela, só grava no branch da sessão. Se não tiver, me diga que eu peço a ele.
3. A "opção 2" (PR de governança para o `git push` pelo clone) deixa de ser necessária para destravar. Se quiser, o `coord.mjs` pode ganhar depois um modo git (e o fuso America/Manaus do R-20261120-091217-po) numa tarefa normal.
4. Este recado já foi gravado assim: é o primeiro do po por `git push`.
