# Economizar o GitHub Actions

## Contexto
Ordem do Alexandre na sessão "BapCentral - Agente PO", 20/11/2026, 10:10 (Manaus). Texto literal:

"ECONOMIZE ACTIONS"

Levantamento do po (só leitura): no aloirr/bapcentral o ci.yml roda só em pull_request, com cancelamento do run anterior do mesmo branch; cada push num PR gasta cerca de 1 min. No aloirr/bapcentral-recados, o aviso-telegram roda a cada push em recados/alexandre/, mas sai "skipped" (Telegram desligado) e não gasta minutos; o issue-recado só roda quando abre issue.

## O que fica decidido
- Um commit e um push por PR, com todas as correções juntas. Lint, testes e smokes rodam na sessão antes do push.
- Não atualizar o branch do PR com o main só por atualizar: só quando houver conflito ou antes do merge, se o CI exigir.
- PR de quadro, tarefas e diário vai junto com outro PR do mesmo dono, nunca sozinho.
- Rerun só por falha de infraestrutura, uma vez.
- Nenhum workflow novo, agendamento ou disparo manual (workflow_dispatch) sem autorização escrita do Alexandre.
- Issue de teste pelo formulário só quando ele pedir.
- O po grava o "Status HHhMM" só quando algo mudou; ronda sem novidade não gera recado (só a linha no chat).
